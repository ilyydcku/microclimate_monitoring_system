# Описание программного проекта

## 1. Индивидуальный вариант

Вариант 17: «Система мониторинга параметров микроклимата».

## 2. Назначение системы

Система предназначена для сбора, хранения, просмотра и анализа параметров микроклимата.

Основная задача системы состоит в предоставлении пользователям актуальной и достоверной информации о параметрах микроклимата и истории их изменения.

Для данного проекта особое значение имеют:

- подлинность источников данных;
- целостность полученных показаний;
- доступность системы и данных мониторинга.

## 3. Пользователи системы

В системе предусмотрены следующие основные роли:

### Оператор

Оператор осуществляет повседневную работу с данными мониторинга:

- просматривает текущие показания;
- просматривает историю измерений;
- выполняет поиск и фильтрацию данных;
- формирует отчеты в пределах предоставленных полномочий.

### Инженер

Инженер выполняет технический анализ данных:

- просматривает текущие и исторические показания;
- анализирует записи о параметрах микроклимата;
- изменяет состояние записей в пределах своих полномочий;
- контролирует корректность данных и источников измерений;
- формирует отчеты.

### Администратор

Администратор отвечает за административные функции системы:

- управляет учетными записями и ролями;
- управляет параметрами системы в пределах предоставленных полномочий;
- контролирует журнал событий безопасности.

Администратор не получает автоматически неограниченный доступ ко всем прикладным данным. Конкретные полномочия определяются матрицей доступа.

## 4. Основные функции системы

| ID | Функция | Кто использует | Основные данные |
|---|---|---|---|
| F-01 | Регистрация показаний параметров микроклимата | Система на основании данных источника | Идентификатор источника, параметры измерения, время |
| F-02 | Просмотр текущих показаний | Оператор, инженер | Значения параметров, источник, время измерения |
| F-03 | Просмотр истории измерений | Оператор, инженер | Исторические записи измерений |
| F-04 | Поиск и фильтрация данных | Оператор, инженер | Параметры поиска, период, источник |
| F-05 | Изменение состояния записи | Инженер | Идентификатор записи, состояние |
| F-06 | Формирование отчетов | Оператор, инженер | Показания, период, параметры отбора |
| F-07 | Управление учетными записями и ролями | Администратор | Учетная запись, роль |
| F-08 | Просмотр журнала событий безопасности | Администратор | Событие, исполнитель, время, результат |

Функции, связанные с аутентификацией, авторизацией и разграничением доступа, в версии v0.2 рассматриваются как требования и планируемое поведение. Их реализация относится к последующим лабораторным работам.

## 5. Обрабатываемые данные

Система предполагает обработку следующих основных категорий данных:

- данные пользователей и их ролей;
- показания параметров микроклимата;
- сведения об источниках измерений;
- статусы и история изменения записей;
- параметры поиска и формирования отчетов;
- записи журнала событий безопасности;
- параметры конфигурации приложения.

Подробное описание категорий данных и защищаемых активов приводится в `docs/assets.md`.

## 6. Границы системы

В границы рассматриваемого проекта входят:

- исходный код приложения в каталоге `app`;
- модуль загрузки и проверки конфигурации;
- логика обработки данных мониторинга, предусмотренная проектом;
- проектная документация;
- автоматические тесты;
- параметры конфигурации приложения;
- предусмотренные проектом хранилище данных и журнал событий;
- механизмы обработки запросов пользователей, которые будут реализовываться поэтапно в последующих версиях.

В рамках лабораторной работы № 2 основным результатом является спецификация требований безопасности. Новые механизмы аутентификации, авторизации и другие защитные механизмы не реализуются.

## 7. Внешние системы и источники данных

Внешними по отношению к рассматриваемому приложению считаются:

- датчики или иные устройства, являющиеся источниками показаний микроклимата;
- каналы передачи данных от источников измерений;
- программная и аппаратная среда, в которой запускается приложение.

При формировании требований безопасности учитывается необходимость подтверждения допустимости источника данных и защиты показаний от неправомерного изменения.

## 8. Ограничения учебной реализации

Проект является учебной реализацией.

Для версии v0.2 принимаются следующие ограничения:

- используются искусственные тестовые данные;
- реальные датчики и производственная инфраструктура не подключаются;
- реальные пароли, ключи и другие секретные данные не включаются в документацию и Git;
- аутентификация и авторизация в рамках лабораторной работы № 2 не реализуются;
- матрица доступа описывает требуемое будущее поведение системы;
- требования безопасности со статусом «сформулировано» не считаются реализованными или проверенными;
- существующий Python-код версии v0.1 сохраняется без изменений, если изменение прямо не требуется заданием.

## 9. Текущее состояние проекта

Версия v0.1 содержит:

- минимальное Python-приложение;
- загрузку и проверку конфигурации;
- безопасную работу с локальным файлом `.env`;
- шаблон `.env.example`;
- автоматические тесты первоначальной версии;
- начальную проектную документацию.

Версия v0.2 расширяет документацию проекта и фиксирует требования безопасности без реализации новых защитных механизмов.
