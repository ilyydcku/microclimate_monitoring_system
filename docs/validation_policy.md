# Политика валидации JSON-заявок v0.5

## 1. Назначение

Практическая работа № 5 "Безопасная обработка пользовательского ввода".
Индивидуальный вариант 17: "Система мониторинга параметров микроклимата".
Модуль `app/validation.py` контролирует учебный JSON-документ заявки до передачи в бизнес-логику. Он дополняет, а не заменяет действующий модуль `app/security/validation.py`, предназначенный для измерений и изменения состояния записи.

Источник значений для всех полей: JSON-сообщение, поступающее от недоверенного отправителя через `stdin` в корневой `main.py`. Данные, полученные снаружи, не используются без проверки.

## 2. Спецификация полей

| Поле | Тип и обязательность | Ограничения и нормализация | Условия отказа и последствия при отсутствии проверки |
| --- | --- | --- | --- |
| `title` | `str`, обязательно | 5-100 символов после `strip()` и NFC; одна строка | Пустое/длинное имя, неверный тип, управляющие символы; некорректные данные в приложении |
| `description` | `str`, обязательно | 20-2000 символов, NFC, CRLF в LF, допускается `\n` | Неверная длина, недопустимые символы, неверный тип; повреждение текстовых записей |
| `category` | `str`, обязательно | 1-30 символов, `strip()`, NFC, `casefold()`; только `network`, `software`, `access`, `other` | Неизвестная категория; обход разрешающего списка |
| `priority` | `int`, обязательно | От 1 до 5; проверяется `type(value) is int` | `True`, строка, `null`, число вне диапазона; ошибочная логика обработки |
| `reporter_ip` | `str` или `null`, необязательно | После нормализации 2-45 символов, IPv4/IPv6 через `ipaddress`, без зоны `%` | Некорректный IP, неверный тип; неверная атрибуция отправителя |
| `attachment_key` | `str` или `null`, необязательно | `strip()`, NFC, 1-20 символов, только `log` (вариант 17) | Неизвестный ключ или путь (`../secret`); обход каталогов / обращение к посторонним файлам |

Отсутствующие необязательные поля трактуются как `None`. Для варианта 17 `attachment_key` не является обязательным; если передан, допустимо исключительно значение `log`.

## 3. Общие правила структуры и отказа

1. Вход только как `bytes`, не более 8192 байт. Ограничение проверяется до разбора JSON.
2. Кодировка UTF-8; верхний уровень должен быть JSON-объектом.
3. Повторяющиеся ключи и специальные числовые константы `NaN`, `Infinity`, `-Infinity` запрещены.
4. Все четыре обязательных поля должны присутствовать; неизвестные поля запрещены.
5. Текст нормализуется как NFC; `Cc`, `Cf`, `Cs` запрещены, кроме `\n` в многострочном описании. В однострочных полях запрещены `U+2028` и `U+2029`.
6. Недопустимые входные данные вызывают `ValidationError(field, safe_message)`. Исключение не содержит исходных значений, секретов и деталей окружения. Отклоненная заявка не передается в бизнес-логику (Fail Secure).
7. После проверки формируется неизменяемый объект `ValidatedRequest`.
8. HTML-подобная строка допускается как обычный текст описания; защита HTML-вывода выполняется отдельно, если будет реализован веб-интерфейс.

## 4. Файловая безопасность и командные инъекции

Вариант 17 допускает только ключ `log`. Пример безопасного соответствия в `app/validation.py`: `FILES = {"log": "network.log"}`; функция `get_attachment_path()` не принимает произвольный пользовательский путь. Папка для вложений не обязана существовать в учебной версии: функция только возвращает разрешенный путь, файл не открывается и не создается.

Для нового механизма не используются `os.system()` и `subprocess.run(..., shell=True)`; непроверенное значение не передается командной оболочке. При использовании изменяемых недоверенной стороной файлов/символических ссылок в реальной системе потребуются дополнительные меры защиты.

## 5. Проверки

- 20 обязательных сценариев раздела 10 методички (включая позитивные).
- 21 эталонный тест `unittest` из раздела 11 и 3 теста индивидуального варианта 17.
- Проверка демонстрационной точки входа `python main.py < example.json` и случая с приоритетом `999`.
- Повторный запуск тестов предыдущих версий через `python -m pytest -q`.

Защищаемые свойства: корректность структуры и значений, целостность прикладных данных, снижение риска обхода каталогов, исключение неожиданных свойств объекта, контролируемый отказ на границе доверия TB-01.
